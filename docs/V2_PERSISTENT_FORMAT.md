# PersonalRag V2 production persistent index format

Date: 2026-08-28  
Status: **FROZEN for Step 1 + Step 2 deterministic content search**

## Identity

- magic: `PRV2IDX1`
- format version: **`2`**
- search/filter semantic id: **`0x0003_0001`**
- Unicode data: **15.1.0**
- immutable generation file: `gen-%020u.prv2`
- advisory current pointer: `CURRENT`

Format v2 is the first production format tied to the frozen Unicode semantics:

- case-sensitive comparison: NFC
- case-insensitive comparison: NFC -> Unicode full default case fold -> NFC
- no NFKC
- Variant D q3/q4/q5 candidate filtering

Format v1 is deliberately rejected. It used the earlier ASCII-fold search semantics and must never be silently loaded as v2.

The generation file is the durable unit. `CURRENT` is advisory: if it is missing, malformed, or references a corrupt generation, the loader scans immutable generations newest-first and opens the newest structurally valid generation.

## Header and sections

The file contains a fixed header plus exactly seven checksummed sections:

1. exact file catalog
2. logical block map
3. unigram block-presence rows
4. bigram block-presence rows
5. adaptive exact global q3 presence
6. rare q3 postings
7. adaptive q4/q5 accelerator

Every section has offset, length, and CRC64-ECMA in the section directory. The whole file also has a CRC64-ECMA footer and total-length marker.

## File catalog

Each file stores:

- exact relative path
  - Unix: raw path bytes
  - Windows: UTF-16LE code units
- selected source byte length
- source CRC64-ECMA
- source modified timestamp in nanoseconds when available

The format never persists a lossy UTF-8 conversion as filesystem identity.

## Block map

Each logical block stores searchable-byte accounting and source spans. Each span stores:

- file id
- source byte start/end
- first logical line number
- logical line count

Content itself is not duplicated in the persistent index. Final verification reads only candidate source spans and preserves hard logical-line boundaries.

The block/filter representation is built from the frozen case-insensitive comparison representation. Case-sensitive queries may share this candidate index, but exact verification uses NFC case-preserving text and therefore only candidate false positives are possible.

## Variant D filter payload

The production format persists Variant D:

- exact unigram/bigram block presence
- adaptive exact q3 global presence
- rare q3 postings
- q4/q5 global Bloom presence
- rare q4/q5 postings

The q4/q5 Bloom filter may have false positives. It may never be used in a way that permits false negatives. A negative result is safe because every indexed q4/q5 key is inserted during build.

Production sparse anchors are reselected using **actual serialized sizes**:

- q3 sparse budget: <= 1.0% selected source
- q4/q5 sparse budget: <= 0.5% selected source
- combined sparse budget: <= 1.5% selected source

Persistent posting offsets are 64-bit.

## Unicode verification

Valid UTF-8 logical lines use the source-contained Unicode 15.1 tables generated by `tools/generate_unicode_tables.py`.

- NFC canonical equivalents match.
- Full default case-fold expansions such as `ß -> ss` are supported.
- Result offsets map back to original UTF-8 bytes.
- Duplicate normalized starts originating from one source scalar are emitted once.
- Empty-match regex end offsets use the original UTF-8 line length, not the normalized byte length.
- Conservative byte-preserving fast paths are used only when they are provably equivalent to the frozen normalization. Composition-capable pairs fall back to the full normalizer.

Wildcard/regex final verification uses the frozen non-backtracking NFA semantics from `V2_SEARCH_SEMANTICS.md`.

## Publish and recovery

1. Build a complete immutable generation in a temporary file.
2. `sync_all` the temporary generation.
3. Rename it to its final generation name. Generation names are immutable and are never overwritten.
4. Update `CURRENT` only after the generation is durable.
5. Sync the store directory where supported.

On Windows, replacing an existing `CURRENT` with `std::fs::rename` is not assumed atomic. Because `CURRENT` is advisory, a remove/replace interruption is recovered by scanning immutable generations.

## Generation / GC invariant

- A newly published generation records its parent generation.
- Generation numbers never reuse an existing generation filename.
- A valid `CURRENT` generation is protected from GC even if newer orphan generations exist.
- GC retains at least two structurally valid generations.
- Corrupt generations do not count toward the fallback-retention minimum.

## Source drift

Normal search validates source metadata before reading candidate spans:

- size must match,
- modified timestamp is compared when available.

`validate_all_sources()` additionally performs full CRC64 validation.

## Capacity and latency acceptance

Capacity is an acceptance gate rather than a prohibition on tiny-corpus indexes; fixed overhead can dominate toy inputs.

Final Step 1 + Step 2 affinity-controlled evidence using the canonical release binary:

| Corpus | index/source | publish | load |
|---|---:|---:|---:|
| 4 MiB | **2.6694%** | 148.8 ms | 1.17 ms |
| 96 MiB | **1.3035%** | 3.987 s | 9.89 ms |
| 256 MiB | **1.2988%** | 13.214 s | 29.21 ms |

At 256 MiB:

- rare q3 `abd`: p50 2.541 ms, 1 block
- rare q4 `wxyz`: p50 2.432 ms, 1 block
- rare q5 `klmno`: p50 2.524 ms, 1 block
- adversarial `abcde`: 0 candidate blocks, approximately 0 ms
- Unicode full-fold `STRASSE` -> source `Straße`: p50 3.201 ms
- NFC-equivalent `CAFÉ` -> source `Cafe + U+0301`: p50 2.444 ms
- indexable regex: p50 78.588 ms
- wildcard: p50 61.707 ms

All measured first-batch cases are below the 300 ms hard target on this affinity-controlled Linux host. Final product acceptance remains Step 7 on the intended Windows environment.

Normative final evidence is under `evidence/step12-final/`.
